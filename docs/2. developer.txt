===============================================================================
1. ENGINE
===============================================================================

Engine objetivo:

    MUGEN 1.0

El personaje utiliza:

    stcommon=common1.cns

No existe actualmente un common1.cns personalizado dentro del char.

MUGEN utiliza el common1.cns estándar de su carpeta data. Cuando Raziel necesita
cambiar un State común, se sobrescribe únicamente ese State desde los CNS
propios.

Ejemplo actual:

    State 0

está redefinido en:

    logic/core/core.cns

De esta forma no es necesario copiar y modificar todo common1.cns.

-----------------------------
logic/core/core.cns
-----------------------------

Contiene estados comunes/persistentes propios de Raziel.

States actuales:

    0   = Stand personalizado
    800 = Throw attempt
    810 = Throw
    820 = Estado del oponente durante Throw
    821 = Continuación / caída del oponente

State 0:

    var(20) = 0
        -> usa Anim 1000
        -> Stand CON espada

    var(20) != 0
        -> usa Anim 0
        -> Stand SIN espada

También conserva lógica relevante del State 0 estándar:
- Reset de velocidad Y.
- Frenado.
- Cambio a State 5050 si Raziel muere.


-----------------------------
logic/core/system.cns
-----------------------------

Es el cerebro global del personaje.

Contiene:

    [Statedef -2]
    [Statedef -3]

Variables GLOBALES congeladas:

    var(20) = ESTADO DE LA ESPADA

        0 = Equipada / en la mano
        1 = Clavada en el suelo
        2 = Lanzada / volando
        3 = Caída en el suelo

    var(21) = REAVER ACTIVO

        0 = Spectral
        1 = Fire
        2 = Air
        3 = Water
        4 = Earth
        5 = Lightning
        6 = Light
        7 = Dark
        8 = Spirit

    var(22) = CARGA DE LA ESPADA

        Actualmente se inicializa a 0.
        La mecánica de carga todavía NO está implementada.

Inicialización actual:

    RoundState = 0
        var(20) = 0
        var(21) = 0
        var(22) = 0

Esto provoca que Raziel inicie cada round con la espada equipada.

También existen límites de seguridad para var(21):

    menor que 0 -> 0
    mayor que 8 -> 8

State -3 conserva actualmente el sonido de aterrizaje para States 52 y 106.

IMPORTANTE:
Aunque var(21) ya está definido, el sistema completo de Reavers todavía NO está
conectado.

-----------------------------
logic/combat/sword.cns
-----------------------------

Contiene actualmente la transición física entre las dos formas.

State 2100:
    CON ESPADA -> SIN ESPADA

    anim = 1005

Durante AnimElem = 8:

    crea Helper
    ID = 6500
    stateno = 7000
    name = "Physical Soul Reaver"

Al terminar la animación:

    var(20) = 1
    ChangeState -> 0

Resultado:
Raziel termina sin espada y la espada queda representada por el Helper.


State 2110:
    SIN ESPADA -> CON ESPADA

    anim = 1006

Al terminar:

    var(20) = 0
    ChangeState -> 0

Resultado:
Raziel regresa al Stand con espada (Anim 1000).

IMPORTANTE:
Actualmente la lógica de recogida NO comprueba distancia a la espada.
Mientras var(20)=1 y Raziel tenga control en suelo, puede ejecutar el State 2110.


-----------------------------
logic/combat/weapon.cns
-----------------------------

Controla la Soul Reaver física cuando está fuera de la mano de Raziel.

Helper:

    ID = 6500

States:

    7000 = Aparición de grieta
    7010 = Espada clavada
    7020 = Recuperando espada
    7030 = Grieta residual / desaparición

Animaciones/Explods utilizados:

    6501 = Aparición de grieta
    6502 = Grieta estable
    6503 = Desaparición de grieta
    6504 = Parte frontal / tapa de la grieta
    6505 = Espada clavada

Composición visual actual:

    6501 / 6502 / 6503
        sprpriority = -5
        -> detrás de los personajes

    6505
        sprpriority = 5
        -> delante de los personajes

    6504
        sprpriority = 6
        -> delante de la espada

Esto crea un falso efecto 3D:

    grieta de fondo
        < personajes
            < espada
                < frente de grieta


State 7000:
- Crea 6501 (grieta apareciendo).
- Crea 6504 (frente).
- 6501 usa `removetime = -1` para no desaparecer al terminar su animación y
  evitar el parpadeo antes de 6502.
- Cuando Root deja State 2100 -> pasa a State 7010.

State 7010:
- Elimina 6501.
- Crea 6502.
- Crea 6505.
- Mantiene/recrea 6504 según el código actual.
- Cuando Root entra a State 2110 -> pasa a State 7020.

State 7020:
- Elimina 6505.
- Mantiene la grieta durante la animación de recuperar.
- Cuando Root deja State 2110 -> pasa a State 7030.

State 7030:
- Elimina 6504.
- Mantiene 6502.
- A Time = 120 elimina 6502 y crea 6503.
- A Time = 180 destruye el Helper.

Escala actual de los Explods:

    0.09,0.09

Posición actual:
- Grietas / frente: aproximadamente `pos = 0,6`
- Espada: aproximadamente `pos = 0,9`

Estas posiciones ya fueron ajustadas visualmente y funcionan con el montaje
actual.

BUGS YA RESUELTOS EN ESTE SISTEMA:
1. Aparecía una copia gigante de Raziel al crear el Helper.
   Se corrigió haciendo invisible la representación propia del Helper.
2. 6501 terminaba y desaparecía antes de que apareciera 6502.
   Se corrigió manteniendo 6501 (`removetime = -1`) hasta el cambio al State
   estable.

logic/commands/raziel.cmd
-----------------------------

Contiene los inputs y State -1.

Cambio de modo actual:

    [Command]
    name = "sword_switch"
    command = y+z
    time = 1

State -1:

    var(20)=0 + sword_switch
        -> State 2100
        -> clavar espada

    var(20)=1 + sword_switch
        -> State 2110
        -> recuperar espada

Las dos entradas requieren:
- Raziel en suelo (`statetype = S`)
- control (`ctrl`)

5. RAZIEL.AIR — ANIMACIONES RELEVANTES ACTUALES
===============================================================================

Animaciones nuevas importantes:

    1000 = Stand con espada

    1005 = Clavando espada
           CON espada -> SIN espada

    1006 = Sacando / recuperando espada
           SIN espada -> CON espada

La Action 1006 utiliza actualmente los frames del grupo 1005 en orden inverso.

Sistema de grieta / espada:

    6501 = aparición de la grieta
    6502 = grieta estable
    6503 = desaparición de la grieta
    6504 = parte frontal de la grieta
    6505 = espada clavada

Action 1:
    -1,-1, 0,0, 0

Se utiliza como animación invisible disponible dentro del AIR.

El AIR conserva además una gran cantidad de animaciones heredadas, incluidos
recursos 7000+ de prototipos antiguos del Reaver. Su existencia en el AIR NO
significa que estén conectados actualmente al sistema nuevo.
